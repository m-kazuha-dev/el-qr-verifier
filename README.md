# 地方税統一QRコード（eL-QR）電文解析・整合性検証ツール

地方税統一規格（JPQR / EMVCo準拠・MPN仕様）に基づいたQRコードの格納データ（255桁のテキスト電文）をパースし、各種チェックディジット（モジュラス10/11、CRC-16）の整合性を瞬時に検証するWebアプリケーションです。

---

## 開発背景・解決した課題

* **業務背景**:
  * 自治体向け基幹系システムの保守運用において、住民の方々へ発送する「地方税の納税通知書・納付書」の発行処理を担当していました。
  * 納付書にはスマホ決済や金融機関窓口で即時納付できる「地方税統一QRコード（eL-QR）」が印字されています。このQRコードの中に格納されているデータ（255桁のテキスト電文）には、納付額・納期限などの納税情報のほか、用途別に異なる複数の規格（銀行向けの「MPN仕様」とスマホ決済向けの「JPQR規格」）が含まれています。
  * さらにデータ内には、それぞれの規格に応じた複数のチェックディジット（※バーコードやクレカ番号の末尾等にある、読み取り誤りや改ざんを検知するための検算用の数字）が組み込まれており、全体の整合性を担保しています。
  * 地方税は毎年の法改正に伴うレイアウト・出力仕様の改修が発生するほか、年度ごとにeL-QR対応税目の拡大（固定資産税、軽自動車税、国民健康保険税など）による新規実装が行われるため、毎年の課税当初時期には「QRコードが仕様通り妥当な値で出力されているか」の厳格な検証テストが必須でした。
  
* **課題**:
  * 255桁の電文内には納税情報（税目、納期限、納付額など）と3種類のチェックディジットが混在していますが、全体を一括で解析・突合できる手段がありませんでした。
  * 従来の現場では仕様ごとに分かれた3つの簡易検証ツールを個別に行き来して確認していた上、それらのツール自体が過去の遺産としてブラックボックス化しており、内部ロジックや計算根拠が不明瞭なまま運用されていました。
  * そのため、電文からの項目切り出しや納付書原本との突き合わせを目視で行う往復作業が発生し、ツールの仕様把握も含めて1件あたり約30分の工数を要する大きな業務ボトルネックとなっていました。

* **解決策**:
  * ブラックボックス化していた仕様書や各種規格（MPN、JPQR/EMVCo）を解読。モジュラス10/11のアルゴリズムは自前でロジックを設計・実装し、可変ウェイト乗算やCRC-16については実績のある適切なライブラリを選定・統合して技術負債を解消しました。
  * 分散していた検証処理を単一のツールに統合し、255桁の電文を一瞬でパースして主要項目（納付額・納期限）の可視化と整合性判定をワンストップで行えるWebアプリケーションを構築。
  * ツールの行き来や目視照合の手間、仕様の属人化を排除し、1件あたりの検証作業時間を30分から6分へと80%削減しました。

## 実務版との差異（ポートフォリオ公開にあたって）

本リポジトリは、コアとなる解析・検証ロジックを誰でも手軽に確認できるよう、Web（Blazor WebAssembly）向けにシンプルに再構成したポートフォリオ版です。実務で運用していた内部ツールとは以下の点が異なります。

* **入力インターフェース**:
  * **実務版**: PC接続のWebカメラ・外部ライブラリ（OpenCV / ZXing等）を用いた帳票QRコードの直接スキャン読み込みに対応
  * **本ツール**: 環境依存を排除しブラウザ上で即座に検証できるよう、255桁電文のテキスト入力に特化
* **表示項目**:
  * **実務版**: 収納機関番号、税目・料金番号、税事務所コード、納期限、支払期限、案件特定キーなど帳票上の全メタデータを網羅的にマッピング表示
  * **本ツール**: 主要項目（納付額・納期限）およびコアとなる各種チェックディジットの検証結果にフォーカスして表示

---

## 主な機能

* **255桁電文のパース**: 納付額、納期限、課税年度などの主要フィールドを即座に分解抽出
* **MPNチェックディジット検証（CD1, CD2）**: 自前実装のモジュラス10/11および可変ウェイト乗算を用いた2桁CDの検証
* **JPQR / EMV準拠 CRC-16検証（CD3）**: 生成多項式 `0x1021`（CRC-16/CCITT-FALSE）による巡回冗長検査の検証

## 技術スタック・アーキテクチャ

* **フレームワーク**: .NET 8 / Blazor WebAssembly
* **言語**: C#

### 設計のポイント
* **UIとドメインロジックの分離**: 計算・検証ロジック（`ElQrValidator`）を画面層から独立させ、単体テストや他プラットフォームへの移植が容易な構造に設計。
* **WebAssemblyによる高速・安全なクライアント実行**: サーバー通信や外部送信を行わず、ブラウザ内のWebAssembly上でC#ロジックを直接実行。機密性のある税務電文の外部流出を防ぎます。

## ローカル実行手順

1. **リポジトリのクローン**
```bash
git clone [https://github.com/m-kazuha-dev/el-qr-verifier.git](https://github.com/m-kazuha-dev/el-qr-verifier.git)
cd el-qr-verifier/ElQrVerifier.Web
```

2. **アプリケーションの起動**
```bash
dotnet watch
```

3. **ブラウザでアクセス**  
起動後、コンソールに表示されるローカルURL（例: `http://localhost:5107` など）をブラウザで開いて利用します。
